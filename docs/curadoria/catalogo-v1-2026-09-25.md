# Curadoria do catálogo de nichos — versão v1 (2026-09-25)

Catálogo global administrado pela Sinergia (`niches`, `subniches`, `subniche_categories`).
Os clientes só escolhem entre estas opções; os IDs de categoria do Mercado Livre nunca aparecem no painel.

## Método

Toda categoria passou por duas validações, só com a API oficial:

1. **Árvore oficial (sem token).** Candidatas geradas por `GET /sites/MLB/domain_discovery/search?q=<termo>`; cada uma conferida em
   `GET /categories/{id}`: precisa ser folha e o `path_from_root` precisa estar no ramo esperado.
   Categorias em ramos incompatíveis (brinquedos, pet, bebês, indústria, antiguidades, móveis…) foram rejeitadas aqui,
   mesmo com nome parecido com o subnicho.
2. **Amostra de produtos (token de produção, só GET).** Executado no Console do serviço `botml` em 2026-09-25 ~13:40 UTC
   (commit em produção 9da4d2c; token só lido, sem gravação; nenhum refresh durante a validação):
   `GET /highlights/MLB/category/{id}` e, para cada resultado do tipo `PRODUCT` (catálogo `MLB…`),
   `GET /products/{id}`. Registrado o `domain_id` de cada produto e o nome das 4 primeiras amostras.
   Não foram usados `/items/{id}`, `/user-products/{id}` (403 na Etapa 0), busca por texto nem scraping.

Critério de aprovação: HTTP 200; pelo menos 8 produtos de catálogo no ranking; pelo menos 85% dos produtos em domínios
compatíveis com o subnicho; amostras coerentes. Os domínios compatíveis ficam gravados em `expected_domains`
(a etapa 4 poderá descartar produtos fora deles). Produtos fora dos domínios esperados estão listados como "desvio".

`hl` = itens no ranking; `mlb` = produtos de catálogo `MLB…` (os demais são `USER_PRODUCT`/`ITEM`, sem acesso).
